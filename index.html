Back & Forward Navigation — Stack

How Last In, First Out (LIFO) powers the Back and Forward buttons.

LIFO (Last In, First Out)

The element placed last into the stack is the very first one removed.

Push Operation

Visiting a new page or stepping backward stores the departing page onto the stack.

Pop Operation

Clicking Back or Forward pops the topmost target URL to display.

Doubly Linked List — Page Connections

An alternative architectural model for bidirectional browser history traversal.

💡 Architecture Note: While modern browsers commonly use two stacks for quick LIFO Back/Forward button history, a Doubly Linked List represents an elegant alternative model where each history record is a standalone node containing bidirectional pointers.
⬅️

Previous Pointer (`prev`)

Allows instant backward navigation to the earlier page without re-allocating memory.

📄

Website Data

Stores the URL, page state, scroll position, and title for the visited node.

➡️

Next Pointer (`next`)

Enables forward traversal when stepping forward through the browsing session.

Tab Management — Array / Dynamic Array

Contiguous indexed memory structures for holding open browser tabs.

Browsers store open tabs in an array or dynamic array (e.g., std::vector, ArrayList, or JS Array). Each tab occupies a contiguous index in memory, allowing instant \(O(1)\) random access when switching tabs.

Access Tab by Index: O(1)
Add Tab at End: O(1) Amortized
Close Tab in Middle: O(n) Shifting

Browsing History Search — Linear Search

Sequential element-by-element scanning through an unsorted chronological log.

"Linear Search checks elements sequentially until the required element is found or the list ends."
Time Complexity: O(n)

Because browser history is ordered chronologically by timestamp (not alphabetically by URL), searching for a specific keyword in an unindexed history list requires inspecting entries one by one from beginning to end.

Hash Table — Fast URL & Cache Lookup (Optional Concept)

Direct \(O(1)\) retrieval using mathematical hashing on URLs.

While Linear Search takes \(O(n)\) time, browsers also rely heavily on Hash Tables (Key-Value mappings) for features requiring instant lookups, such as DNS caching, favicon lookups, and visited site metadata.

Average Lookup: O(1) Constant Time Under suitable conditions and low collisions.
